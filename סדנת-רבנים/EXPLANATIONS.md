## נקודה 1 — מה זה AI ו-LLM

**AI** — מחשב שלמד מכמויות עצומות של טקסט עד שהוא מסוגל לענות על שאלות ולכתוב כמו אדם.

**LLM** (Large Language Model) — המנוע הספציפי שעושה את זה. Claude, GPT — כולם LLM.

**איך זה עובד:**
- הוזנו לו מיליארדי משפטים מאינטרנט, ספרים, מאמרים
- הוא למד לנחש: "אחרי המילים האלה — מה המילה הכי הגיונית הבאה?"
- התשובה היא **הסתברותית** — הוא לא "יודע", הוא מחשב מה הכי סביר

**למה יש כל כך הרבה מנועי AI:**
- כל חברה אספה מידע ממקומות שונים ואימנה מודל משלה
- GPT — OpenAI/מיקרוסופט
- Claude — Anthropic
- Gemini — Google
- כל מודל למד על מידע שונה → לכן תשובות שונות לאותה שאלה

## נקודה 1ב — מה זה לאמן מודל

**לאמן מודל** = להאכיל מחשב במיליארדי משפטים ולגרום לו ללמוד דפוסים.

**איך זה נעשה:**
1. לוקחים מיליארדי משפטים
2. מסתירים מילה אחת בכל משפט
3. המחשב מנחש מה המילה החסרה
4. אם טעה — מתקנים (backpropagation)
5. חוזרים על זה טריליוני פעמים

**כמה עולה:** אימון מודל גדול = עשרות מיליוני דולר. רק חברות ענק עושות את זה.

## נקודה 2 — מה זה תוכנה ואיך היו בונים קודם

**מה זה תוכנה:**
קבצי טקסט כתובים בשפת תכנות — בתוכם פקודות והתניות שאומרות לממשק מה לעשות בכל רגע נתון:
- אם לחצת כאן → קורה X
- אם המידע הוא כך → קורה Y
- כל הלוגיקה של האפליקציה חיה בקבצים האלה

**איך היו בונים קודם:**
- מפתח שלמד שנים
- עלה עשרות אלפי דולר
- לקח חודשים

**מה השתנה:**
Claude Code קורא את הפקודות שלך בעברית פשוטה — וכותב את קבצי הטקסט האלה בשבילך.

**המסר לרבנים:**
> "אתם תמיד ידעתם מה אתם רוצים — רק לא ידעתם לכתוב את קבצי הטקסט. עכשיו יש מישהו שכותב אותם במקומכם."

## נקודה 3 — הרב הוא המנהל, Claude Code הוא הידיים

**מה הרב לא הופך להיות:** מתכנת.

**מה הבעיה שאנחנו פותרים:**
רבנים בחו"ל עובדים לרוב ללא מזכירות, ללא צוות, ללא משאבים. הם מחזיקים בראש כמות עצומה של מידע על אנשים, אירועים, תהליכים — וצריכים לנהל את כל זה לבד.

**שלוש בעיות עיקריות:**
1. **עומס מידע** — הרב צריך לזכור הכל על כולם בכל רגע
2. **מידע שלא מועבר** — כשרב עוזב, הכל נעלם. הרב הבא מתחיל מאפס
3. **אין זמן לדברים הקטנים** — הרב תקוע על משימות ניהוליות במקום לעשות את עבודתו האמיתית

**מה Claude Code נותן:**
- מערכת שמחזיקה את כל המידע במקום אחד
- כלים שעושים את הדברים הקטנים אוטומטית
- תיעוד שמאפשר המשכיות — הרב הבא בונה על מה שכבר נבנה

**המסר המרכזי:**
> "אתה לא הופך למתכנת. אתה הופך לרב שיש לו כלים."

**מה זה טוקן:**

**שלוש אפשרויות:**

| | Pro בלבד | API בלבד | שניהם |
|---|---|---|---|
| claude.ai | ✅ | ❌ | ✅ |
| Claude Code | ❌ | ✅ | ✅ |
| מחיר | $20 קבוע | לפי שימוש | שניהם |

**לסדנה — מה הרבנים צריכים:**
רק API — כי אנחנו עובדים ב-Claude Code.
Pro זה בונוס — אם רוצים גם לשוחח עם Claude בדפדפן.

**המסר לרבנים:**

## נקודה 9 — API, טוקנים ואבטחה

### מה זה API — משל הבית

כל מערכת בענן היא כמו בית. לבעל הבית יש גישה מלאה פנימה.
אבל אפשר גם לפתוח דלת לאנשים מבחוץ — עם כללים:
מי מורשה להיכנס, מה מותר לו לעשות, ובאיזו שפה לדבר.

כך בדיוק עובד API — זו הדלת הרשמית לכל מערכת.

---

### שפה ושיטת גישה

כל API מגדיר מראש:
- **מה מותר לעשות** — GET (לקחת), POST (להוסיף), DELETE (למחוק)
- **באיזו שפה** — בדרך כלל JSON (פורמט תקשורת סטנדרטי)
- **מה הכללים** — מתועד ב-Documentation של כל מערכת

---

### רמות רגישות של פעולות

| פעולה | דוגמה | רגישות |
|---|---|---|
| GET — לקרוא מידע | לראות רשימת אנשים | רגיש |
| POST — להוסיף מידע | להוסיף אדם חדש | יותר רגיש |
| DELETE — למחוק מידע | למחוק רשומה | הכי רגיש |

---

### קוד כניסה = טוקן API

כמו קוד לדלת הבית. בלי קוד — אין כניסה.
הטוקן הוא המפתח לכל המידע באותה מערכת — לכן הוא רגיש מאוד.
**כל מערכת מערכת נותנת טוקן משלה** — Anthropic, Google, WhatsApp, וכו'.

---

### Frontend vs Backend — למה הטוקן לא חשוף

```
המשתמש (דפדפן)
      ↓
  Frontend        ← רץ אצל המשתמש — כולם יכולים לראות
      ↓
  Backend         ← רץ על שרת של Vercel/Render — אף אחד לא יכול לגשת
      ↓
  API חיצוני     ← Anthropic, Google, וכו'
```

**הטוקן נמצא רק ב-Backend.** כשהמשתמש לוחץ כפתור:
1. הדפדפן שולח בקשה לשרת שלך
2. השרת (שאף אחד לא יכול לפתוח) לוקח את הטוקן מה-Environment Variable
3. השרת פונה ל-API החיצוני
4. התשובה חוזרת למשתמש — הטוקן לא עבר דרכו אף פעם

**הסכנה:** אם הטוקן נמצא ב-Frontend — כל אחד שלוחץ קליק ימני ← Inspect יכול לראות אותו ולהשתמש בו.

---

### איפה שומרים את הטוקן

**בפיתוח על המחשב — קובץ `.env`:**
קובץ מקומי שנמצא רק על המחשב שלך. לא עולה ל-GitHub. הקוד קורא ממנו בלי לחשוף את הערך.

**בענן (Vercel, Render, Supabase) — Environment Variables:**
לא קובץ — אלא הגדרה בממשק של הפלטפורמה. הם שומרים את זה מוצפן בצד שלהם. הקוד כותב `process.env.MY_TOKEN` — השרת יודע מה זה, הדפדפן לא.

---

### שכבות אבטחה בסיסיות

| שכבה | מה עושים |
|---|---|
| קוד | לא לשים טוקנים בקוד — רק ב-env |
| שרת | רק HTTPS — לא HTTP |
| API | Rate limiting — מגבילים כמה בקשות בדקה |
| GitHub | `.gitignore` על קובץ `.env` — לא עולה לענן |

**בדיקת אבטחה עם Claude Code:**
הרב יכול לשאול: *"בדוק אם יש דליפות אבטחה בקוד שלי"* — Claude Code יסרוק ויגיד אם משהו חשוף.

## נקודה 9ב — חיבור Claude Code למערכות חיצוניות (MCP)

### מה זה MCP

עד כה Claude Code בנה דברים — כתב קוד, יצר קבצים.
אבל אפשר לחבר אותו למערכות אמיתיות — ואז הוא לא רק בונה, הוא **עושה**.

**MCP** (Model Context Protocol) — הפרוטוקול הסטנדרטי שמאפשר לClaude Code לדבר עם מערכות חיצוניות.

---

### ההבדל בין API ל-MCP — משל המשרת

חוזרים למשל הבית:

- **הבית** = המערכת (WhatsApp, Gmail, CRM)
- **API** = הדלת עם הכללים. אתה נכנס — אבל צריך לדעת בעצמך איפה כל חדר, איפה כל ארון, ואיך כל דבר עובד בפנים
- **MCP** = משרת שעומד בכניסה. אתה מדבר רק איתו בשפה פשוטה — והוא יודע איפה הכל ומסדר בשבילך

Claude מדבר עם המשרת (MCP Server). המשרת מכיר את הבית לעומק. Claude לא צריך להיכנס לבד.

**בפועל:** Anthropic הגדירו כלל אחד — "כל מי שרוצה לתת לClaude כלי, יבנה משרת בצורה הזו." עכשיו כל מערכת (WhatsApp, Gmail, Supabase) בנתה משרת משלה. Claude מדבר עם כולם באותה שפה.

> **MCP = USB לכלים של AI.** לפני USB — לכל מכשיר חיבור אחר. אחרי USB — הכל מתחבר אותו הדבר. MCP עשה את אותו הדבר לAI.

---

### מה Claude Code יכול לעשות כשמחובר

| מערכת | מה הוא יכול לעשות |
|---|---|
| WhatsApp | לשלוח הודעות לאנשי הקהילה |
| Gmail | לשלוח ולקרוא אימיילים |
| Google Calendar | ליצור ולנהל אירועים |
| CRM | להכניס, לעדכן, לחפש אנשי קשר |
| Supabase | לקרוא ולכתוב לבסיס הנתונים |
| ועוד... | כל מערכת שיש לה API |

**לרב:** במקום לשלוח ברכת יום הולדת ידנית — Claude Code עושה את זה לבד.

---

### ⚠️ אבטחה — הגדרת הרשאות לסוכן

כשהסוכן יכול לעשות דברים בעולם האמיתי — חייבים להגדיר גבולות ברורים.

**שלוש רמות הרשאה:**

| רמה | מה זה אומר | דוגמה |
|---|---|---|
| **מותר תמיד** | הסוכן עושה לבד, בלי לשאול | לקרוא מידע מהמערכת |
| **צריך אישור** | הסוכן שואל לפני שמבצע | לשלוח הודעת WhatsApp |
| **אסור בכלל** | הסוכן לא יכול לגעת בזה | למחוק נתונים |

**המסר לרבנים:**
> לפני שנותנים לסוכן כלים — מגדירים מה מותר לו. סוכן שיכול לשלוח הודעות לבד זה כוח גדול — צריך להיות זהיר.

## נקודה 10 — Git ו-GitHub

### מה זה Git

מערכת גיבוי חכמה לקוד. כמו "Track Changes" בוורד — אבל לא רק שינויים אחרונים, כל הגרסאות מאז תחילת הפרויקט.

**למה חשוב:** Claude Code כותב הרבה קוד. לפעמים שינוי אחד שובר הכל. בלי Git — אי אפשר לחזור. עם Git — כפתור אחד ואתה חוזר לגרסה שעבדה.

---

### Git vs GitHub

| | מה זה | איפה |
|---|---|---|
| **Git** | מערכת גיבוי גרסאות | על המחשב שלך |
| **GitHub** | אותו דבר — בענן | באינטרנט |

Git = הכלי. GitHub = המקום שבו שומרים את הגיבוי.

---

### איך עובד

```
עשית שינויים בקוד
      ↓
git commit — שמרת "נקודת ביקורת" עם תיאור קצר
      ↓
git push — העלית לענן (GitHub)
```

כל commit הוא צילום מצב שלם של הפרויקט באותו רגע. אפשר תמיד לחזור אליו.

**החוק הפשוט:**
> כל פעם שמשהו עובד — Commit. כמו לשמור משחק לפני מעבר לשלב קשה.

---

### האם כולם יכולים לראות את הקוד ב-GitHub?

GitHub נותן שתי אפשרויות:
- **Public** — כולם רואים (בדרך כלל קוד פתוח)
- **Private** — רק אתה ומי שהזמנת

הרבנים יפתחו **Private** — אף אחד לא רואה כלום.

---

### מה עולה ל-GitHub ומה לא

| מה עולה | מה לא עולה |
|---|---|
| הקוד (ההוראות) | קובץ `.env` (הטוקנים) |
| מבנה הפרויקט | בסיס הנתונים (אנשי הקהילה) |
| ה-CLAUDE.md | כל מידע פרטי |

**GitHub שומר את ה"מתכון" — לא את ה"אוכל".**

מידע על אנשי הקהילה יושב ב-Supabase (בסיס הנתונים) — מקום אחר לגמרי, מוגן בנפרד.

---

### לסיכום לרבנים
1. פותחים Private repo — רק הרב רואה
2. הקוד עולה — הסודות לא (בזכות `.gitignore`)
3. נתוני הקהילה לא נוגעים ל-GitHub בכלל

### הפתרון — CLAUDE.md

**דוגמה לרב:**

## נקודה 12 — Skills vs Agents

### ההבדל הבסיסי

| | Skill | Agent |
|---|---|---|
| **מה זה** | פעולה חוזרת עם צעדים קבועים | מומחה עם הקשר וזיכרון |
| **מתי** | תמיד אותו הדבר | עבודה שדורשת שיקול דעת |
| **דוגמה** | "סגור סשן", "בדוק אבטחה" | יצי, מכון, שירותי קודש |

---

### מתי בונים Skill

כשאפשר לכתוב את הפעולה כרשימת צעדים — תמיד אותו הדבר:
- "בדוק אבטחה בקוד"
- "סגור סשן ועדכן STATUS"
- "פתח בוקר עם רוני"

### מתי בונים Agent

כשצריך מישהו שמבין הקשר, לומד, ומחליט:
- יצי — מחליט איך לבנות תוכנית לפי הקהל הספציפי
- מכון — מכיר את הפרויקט לעומק ויודע מה מתאים

---

### Skill גלובלי vs Skill ספציפי

| סוג | איפה יושב | דוגמה |
|---|---|---|
| **גלובלי** | `skills/` — זמין לכולם | בדיקת אבטחה, סגירת סשן |
| **ספציפי לסוכן** | בתוך ה-CLAUDE.md של הסוכן | "בנה SESSION חדש" — רק ליצי |

**דוגמה מעשית:**
- בדיקת אבטחה → גלובלי. כל סוכן וכל פרויקט צריך את זה.
- "בנה מפגש לסדנה" → ספציפי ליצי בלבד — אחרים לא צריכים את זה.

---

### המסר לרבנים
> "Skill = מתכון. Agent = שף. המתכון תמיד אותו הדבר — השף מחליט מה לבשל."

## נקודה 13 — הכלים מאחורי הגב: GitHub, Vercel, Supabase, Cloudflare

### GitHub — ארכיון הקוד

| | |
|---|---|

### Vercel — מעלה את האפליקציה לאינטרנט

אתה כותב קוד, דוחף לGitHub — Vercel לוקח את זה ומפרסם באינטרנט אוטומטית.
בלי Vercel — האפליקציה יושבת רק על המחשב שלך.

| | |
|---|---|
| **מחיר** | חינם לבסיסי, מ-$20 לחודש לצרכים גדולים |

| **חיסרון** | האפליקציה "נרדמת" אחרי חוסר פעילות בחינם |

---

### Supabase — בסיס הנתונים

כאן יושב המידע: אנשי הקהילה, ימי הולדת, יארצייטים, כל הרשומות.
יש ממשק ויזואלי — הרב יכול לראות את הנתונים כמו טבלת Excel.

| | |
|---|---|
| **מחיר** | חינם עד 500MB, מ-$25 לחודש לצרכים גדולים |
| **חלופות** | Firebase (Google — יקר יותר), Airtable (פשוט אבל מוגבל) |
| **יתרון** | חינם, קל, ויזואלי. לקהילה של 200 אנשים — מספיק לשנים |
| **חיסרון** | נקפא אחרי שבועיים בלי שימוש בחינם |

**האם המידע בטוח?**
Supabase רץ על שרתי Amazon — אותם שרתים שGmail ורוב האינטרנט רצים עליהם. המידע מוצפן. הסיכון האמיתי הוא מי מחזיק את המפתחות (ה-API Key) — לכן חשוב לשמור אותם ב-env ולא לחשוף אותם. רמת האבטחה גבוהה בהרבה מקובץ Excel על שולחן העבודה.

---

### Render — פלטפורמה לשרתים ובאקאנד

כמו Vercel — אבל מתאים יותר לשרתים שרצים ברקע.

| | Vercel | Render |
|---|---|---|
| **הכי טוב ל** | אתרים ופרונטאנד | שרתים ובאקאנד |
| **שפות** | בעיקר JavaScript | כל שפה — Python, Node, Go |
| **דאטהבייס** | לא כולל | כולל PostgreSQL פשוט |
| **מחיר** | חינם עם "שינה" | חינם עם "שינה", מ-$7 בלי |

**לרבנים בפועל:**
- אתר / דשבורד → Vercel
- סוכן שרץ ברקע ושולח התראות → Render

---

### מה זה "שינה" (Cold Start)

בחינם, הפלטפורמות לא מחזיקות את השרת פעיל כל הזמן.
כשאין בקשות במשך 15-30 דקות — הן "כובות" את השרת.

**מה קורה כשמישהו נכנס:**
השרת צריך להתעורר → לוקח 10-30 שניות → המשתמש מחכה.

**משל:** כמו חנות שסוגרת בין לקוחות. הלקוח הבא מחכה שהמוכר יפתח ויסדר לפני שיוכל להיכנס.

**מתי זה בעיה ומתי לא:**

| מצב | בעיה? |
|---|---|
| דשבורד שרק הרב פותח בבוקר | קטנה — מחכה 20 שניות |
| אתר שמשתמשים נכנסים לפעמים | קטנה — מחכים קצת |
| סוכן שצריך לשלוח התראות ב-8 בבוקר | **גדולה** — השרת ישן, ההתראה לא יוצאת |

**הפתרון:** לשלם $7-20 לחודש — השרת פעיל 24/7 בלי שינה.

---

### Cloudflare — הגנה ומהירות (שלב מתקדם)

Cloudflare עושה שני דברים:

**1. הגנה:**
- CDN — שומר עותקים של האתר ב-200 מדינות → המשתמש מקבל תגובה מהירה מהשרת הקרוב
- DDoS — מגן מפני התקפות שמנסות להפיל את האתר
- Firewall — חומת אש מפני ניסיונות חדירה

**2. פריסה לאינטרנט (חלופה לVercel):**
- Cloudflare Workers + Pages — אחסון והרצת קוד

**Cloudflare vs Vercel:**

| | Vercel | Cloudflare |
|---|---|---|
| **קלות שימוש** | פשוט מאוד | יותר מורכב |
| **חינם** | יש — אבל "נרדם" | יש — לא נרדם |
| **אבטחה** | בסיסית | חזקה מאוד |
| **למי מתאים** | למתחילים | לצרכים מתקדמים |

**לרבנים:** מתחילים עם Vercel. כשהמערכת גדלה ויש צורך באבטחה חזקה יותר — עוברים לCloudflare.

## נקודה 18 — לוח עברי ומנגנון התראות

### אתגר הלוח העברי

**בעיה 1 — יום / לילה (לפני / אחרי שקיעה)**

בהלכה היום מתחיל בשקיעה. אם הלידה אחרי שקיעה — ה"יום" ההלכתי הוא כבר המחרת.

**בעיה 2 — כל שנה התאריך הלועזי משתנה**

י"ח אדר יכול להיות פברואר שנה אחת ומרץ שנה אחרת. ובשנה מעוברת — אדר א' או אדר ב'?

**הפתרון לשתי הבעיות — Hebcal API:**
- מחשב שקיעות לפי מיקום ותאריך
- ממיר תאריכים עבריים ללועזיים לכל שנה אוטומטית
- מטפל בשנה מעוברת

המערכת שומרת: תאריך עברי + לפני/אחרי שקיעה + מיקום הקהילה.
Hebcal מחשב את השאר לבד.

---
